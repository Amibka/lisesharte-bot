# Lisesharte Bot

Учебный Telegram-бот для общения с локальной языковой моделью через LM Studio. Сделан как прототип, чтобы разобраться с асинхронным Python, API и хранением истории диалога.

## Что работает

- Принимает сообщения в Telegram и передаёт их в FastAPI.
- Отправляет историю диалога в LM Studio.
- Получает от модели JSON с действиями: отправить ответ, поставить реакцию и другие действия Telegram.
- Проверяет структуру действий через Pydantic и выполняет их по очереди.
- Сохраняет сообщения в SQLite и использует Redis для доступа к истории.

Основной стек: Python 3.14, aiogram, FastAPI, SQLAlchemy/SQLModel, Alembic, Redis и httpx.

## Как запустить

Нужны Python 3.14, uv, запущенный Redis и LM Studio с доступной моделью и включённым API-сервером.

Установить зависимости:

```bash
uv sync
uv pip install sqlmodel alembic redis aiosqlite uvicorn
```

Часть зависимостей пока не внесена в `pyproject.toml`, поэтому устанавливается отдельно второй командой.

Создать `.env` в корне проекта:

```dotenv
BOT_TOKEN=токен_бота_из_BotFather
IP=127.0.0.1
PORT=8000
REDIS_URL=redis://localhost:6379/0
DB_PROVIDER=sqlite
SQLITE_DB_NAME=memory_storage.db
LLM_PROVIDER=lm_studio
MODEL=идентификатор_модели_в_LM_Studio
CONTEXT_LENGTH=8192
LM_STUDIO_IP=127.0.0.1
LM_STUDIO_PORT=1234
```

Запустить из корня проекта:

```bash
uv run main.py
```

При запуске применяются миграции, поднимается FastAPI и запускается Telegram-бот. Для локальной модели также выполняется проверка загрузки в LM Studio.

## Ограничения

Это рабочий прототип, разработка которого пока остановлена. В проекте есть тесные связи между модулями, нет автоматических тестов, а настройка с нуля требует ручных действий. Ответы модели могут приходить в неправильном формате; часть таких случаев обрабатывается, но полноценного восстановления после ошибок пока нет.

В следующем проекте хочу выделить отдельный объект бота и подключать к нему память, модель и инструменты через понятные интерфейсы. Так будет проще менять отдельные части и проверять их независимо.
